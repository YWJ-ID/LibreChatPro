# 登录页内化为聊天工作台认证弹窗设计

## 1. 背景与目标

当前未登录用户访问应用时，会先进入独立认证页面，再进入聊天工作台。本需求将认证入口内化到聊天工作台：未登录用户首屏直接看到聊天界面，执行需要身份的操作时，阻止该操作并在当前聊天页面上打开认证弹窗。

本需求只改变认证入口和页面承载方式，不新增认证方式，不改变后端认证协议和认证规则。

目标流程：

```text
访问应用
  → 直接显示聊天工作台
  → 未登录用户可以浏览并编辑输入内容
  → 执行需要身份的操作
  → 阻止操作并打开认证弹窗
  → 完成认证后关闭弹窗
  → 保留聊天输入
  → 用户再次触发原操作
```

登录成功后不得自动发送原问题、自动上传文件或自动重放其他被阻止的操作。

## 2. 已确认范围

### 2.1 保留的认证能力

认证弹窗必须保留当前独立认证页已有的能力：

- 账号密码登录；
- LDAP 用户名登录（由现有配置决定）；
- Turnstile 验证（由现有配置决定）；
- 登录错误提示、限流、封禁和邮箱未验证处理；
- 重新发送验证邮件；
- 用户注册；
- 忘记密码；
- 重置密码；
- TOTP 2FA；
- 2FA 备用恢复码；
- 当前配置启用的 Google、Facebook、GitHub、Discord、Apple、OpenID、SAML 登录；
- 当前多语言文案和认证校验规则；
- 当前注册成功提示与 3 秒倒计时；
- 邮箱验证及验证邮件重发。

### 2.2 明确不新增的能力

- 二维码登录；
- 手机号或短信验证码登录；
- 微信登录；
- 新的 SSO provider；
- 匿名真实模型请求；
- 匿名服务端会话或历史；
- 登录成功自动发送；
- 登录成功自动上传文件；
- 登录成功自动恢复或重放被阻止操作；
- 新的用户模型、Token 机制或认证接口。

## 3. 用户体验与业务规则

### 3.1 匿名首屏

未登录访问 `/`、`/c/new` 或聊天会话入口时：

- 直接显示聊天工作台；
- 不自动跳转到独立 `/login`；
- 不自动打开认证弹窗；
- 显示基础聊天壳层、输入框、发送入口和默认模型展示；
- 模型展示为默认值且不可切换；
- 隐藏或禁用依赖用户数据的历史、账户、余额、订单、Agent、插件、工具、文件和语音功能；
- 允许用户输入、编辑和清空问题；
- 不加载或请求需要用户身份的数据。

匿名工作台不得因为 `isAuthenticated === false` 返回空白页面。

### 3.2 发送拦截

点击发送、按 Enter、快捷 Prompt 或其他发送入口时，必须在 `submitMessage` 之前检查认证状态：

```text
无效/空输入
  → 保留原有表单校验，不打开认证弹窗

有效输入 + 未登录
  → 阻止提交
  → 不调用聊天接口
  → 不创建服务端会话
  → 不上传文件
  → 不清空输入
  → 打开登录弹窗

有效输入 + 已登录
  → 执行现有发送逻辑
```

登录弹窗关闭或登录成功后：

- 原输入继续保留；
- 不自动发送；
- 不排队保存待执行 action；
- 用户必须再次点击发送或按 Enter。

### 3.3 统一认证拦截

所有需要用户身份的操作使用统一的 `requireAuth` / `useRequireAuth` 机制：

```text
已登录
  → 执行原 action

未登录
  → 不执行 action
  → 打开登录弹窗
  → 不保存、不排队、不自动重放 action
```

第一阶段纳入统一拦截的操作：

- 消息发送、Enter 发送、语音发送；
- 文件选择和上传；
- 历史会话查看、搜索、分页和加载；
- 新建或保存服务端会话；
- 会话重命名、删除、收藏、归档、分享、导出和设置修改；
- Agent、插件、MCP、工具和需要角色权限的 Skills；
- 账户设置、用户资料、余额、用量、订单和充值；
- 其他会调用需要 JWT 的业务接口。

以下操作不拦截：

- 浏览聊天壳层；
- 输入、编辑和清空文本；
- 切换主题；
- 打开、关闭和切换认证弹窗；
- 认证弹窗内部的登录、注册、密码重置、邮箱验证、2FA 和 OAuth 操作。

已登录但无权限的操作继续显示原有权限错误，不转换成登录弹窗。

### 3.4 文件与语音

未登录点击文件按钮时，应优先在打开文件选择器前拦截；如果组件限制无法提前拦截，则必须在文件写入状态、预览或上传队列前拦截。不得调用上传接口、保存文件状态或在认证成功后自动重选/上传。

未登录点击录音时直接打开登录弹窗，不开始录音。已有语音结果提交时同样阻止发送。认证完成后不自动恢复录音或发送语音。

### 3.5 弹窗背景

- 聊天工作台继续渲染，不卸载、不重置；
- 增加半透明遮罩；
- 背景不可点击、不可编辑、不可滚动穿透；
- 认证弹窗关闭后恢复背景交互；
- 聊天输入、模型展示、主题和页面位置不因弹窗生命周期被清空；
- 弹窗使用可访问 Dialog 语义、焦点管理、Escape 关闭和响应式布局；
- 弹窗通过 Portal 或等效方式渲染，避免被聊天区域的层叠上下文遮挡。

## 4. 认证弹窗与流程

### 4.1 认证步骤

认证弹窗只使用当前已有认证功能，步骤定义为：

```ts
type AuthModalStep =
  | 'login'
  | 'register'
  | 'forgot-password'
  | 'reset-password'
  | 'two-factor'
  | 'verify-email';
```

默认步骤为 `login`。弹窗内部步骤切换不跳转到独立认证页面。

### 4.2 组件边界

#### AuthModalProvider

职责：

- 管理弹窗打开状态和当前步骤；
- 解析并同步 URL 中的 `auth` 参数；
- 提供 `openAuthModal`、`closeAuthModal` 和步骤切换接口；
- 监听认证成功、注册成功、邮箱验证和密码重置结果；
- 清理认证 URL 参数；
- 不管理聊天输入和待执行 action。

建议接口：

```ts
type AuthModalContextValue = {
  isOpen: boolean;
  step: AuthModalStep | null;
  openAuthModal: (step?: AuthModalStep) => void;
  closeAuthModal: () => void;
  setAuthStep: (step: AuthModalStep) => void;
};
```

#### AuthModal

职责：

- 遮罩、卡片、关闭按钮、Escape 和焦点管理；
- 阻止背景交互；
- 根据步骤渲染 `AuthFlow`；
- 负责桌面和移动端布局。

不负责认证 API、业务拦截和聊天草稿。

#### AuthFlow

负责把现有认证组件改造成可嵌入流程的步骤：

```text
AuthFlow
├── LoginStep
├── RegistrationStep
├── ForgotPasswordStep
├── ResetPasswordStep
├── TwoFactorStep
└── EmailVerificationStep
```

现有 `LoginForm`、`Registration`、`RequestPasswordReset`、`ResetPassword`、`TwoFactorScreen` 和 `VerifyEmail` 的接口、校验、mutation、错误和文案语义应保留，但需解除对独立页面容器、`useOutletContext` 和强制 `navigate` 的耦合。

#### requireAuth

统一认证拦截应在实际 action 入口执行，而不是只给单个按钮绑定点击事件。至少需要覆盖表单提交、键盘提交、语音提交和内部直接调用发送函数的路径。

建议返回：

```ts
type AuthGuardResult = 'allowed' | 'blocked';
```

不得保存或排队 `pendingAction`，避免认证成功后意外发送、上传或进入历史会话。

### 4.3 登录流程

- 登录表单沿用当前字段和校验；
- 失败错误显示在弹窗内并允许重试；
- 429、403、422、500 等错误继续使用现有错误映射；
- 邮箱未验证时保留重发入口；
- 普通登录成功后更新 `AuthContext`；
- 清理 `auth` 参数并关闭弹窗；
- 保留当前聊天上下文和输入；
- 不执行被阻止的原 action；
- 不自动发送问题。

### 4.4 2FA 流程

登录接口返回 `twoFAPending` 时：

- 保持弹窗打开；
- 切换到 `two-factor` 步骤；
- 支持 6 位 TOTP 和备用恢复码；
- `tempToken` 只保存在内存状态，不写入 URL；
- 验证成功后更新认证状态、清理临时状态、关闭弹窗；
- 不自动发送、不重放原 action；
- 关闭弹窗或刷新导致内存 token 丢失时，重新回到登录流程。

### 4.5 注册流程

保留当前注册字段、校验、Turnstile、接口和成功提示：

```text
注册成功
  → 显示现有成功提示
  → 3 秒倒计时
  → 关闭弹窗并清理 auth
  → 不自动登录
  → 不自动发送
  → 保留聊天输入
```

### 4.6 密码重置流程

忘记密码在弹窗内提交当前请求接口和提示。邮件重置链接携带的 `token` 和 `userId` 只传给重置步骤，不写入聊天内容或普通日志。

重置成功后显示现有成功内容并回到登录步骤；不自动登录、不自动发送。成功、取消或失效后清理敏感 URL 参数。

### 4.7 邮箱验证流程

邮箱验证链接在聊天背景上打开验证步骤，自动执行现有验证 mutation，保留成功、失败、重发和倒计时行为。验证成功不自动发送聊天输入。

### 4.8 OAuth / OpenID / SAML

弹窗保留当前配置驱动的 provider 列表和入口，点击后继续跳转现有 `/api/oauth/*` 路径。第三方认证页面不要求嵌入当前弹窗。认证成功返回聊天页并关闭弹窗；失败返回聊天页打开登录步骤并显示 OAuth 错误。

## 5. URL 与路由

### 5.1 认证参数

URL 只接受固定认证步骤：

```text
auth=login
auth=register
auth=forgot-password
auth=reset-password
auth=verify-email
auth=2fa
```

认证步骤切换使用 `replace`，避免每次步骤切换增加历史记录。通过聊天内动作打开弹窗时新增 URL 历史；浏览器后退关闭弹窗，前进可重新打开。关闭弹窗清理 `auth` 和本次认证临时参数。

### 5.2 旧路由兼容

旧路由不再渲染全屏认证页，而是转换到聊天路由并打开对应步骤：

```text
/login
  → /c/new?auth=login

/register
  → /c/new?auth=register

/forgot-password
  → /c/new?auth=forgot-password

/reset-password?token=x&userId=y
  → /c/new?auth=reset-password&token=x&userId=y

/verify?token=x&email=y
  → /c/new?auth=verify-email&token=x&email=y
```

`redirect_to` 继续使用现有安全校验，只允许站内安全相对路径，拒绝绝对 URL 和协议相对 URL。

### 5.3 刷新与历史

- `/c/new?auth=login` 刷新后恢复登录弹窗；
- 无 `auth` 的聊天 URL 刷新后不自动弹窗；
- `tempToken` 不写 URL，因此 2FA 刷新后无法恢复，回到登录流程；
- 关闭弹窗使用 `replace` 清理参数，避免关闭后后退再次无意打开；
- 登录成功后保留当前安全聊天路径，不无条件覆盖为 `/c/new`。

## 6. 匿名数据和请求边界

匿名状态下优先由前端认证状态拦截，不以“请求后收到 401”作为主流程：

- 用户、历史、模型权限、端点、Agent 等 query 设置为未登录禁用；
- 只渲染静态或默认展示；
- 不创建服务端会话；
- 不调用真实模型接口；
- 401 作为兜底时打开同一认证弹窗，不跳转独立 `/login`；
- 同一请求产生的重复 401 只触发一次弹窗。

错误分层：

```text
未认证 → 认证弹窗
已认证但无权限 → 原权限错误
服务端/网络失败 → 原错误提示
认证接口失败 → 弹窗内错误
```

## 7. 测试与验收

### 7.1 路由和 URL

必须覆盖：

- `/login`、`/register`、`/forgot-password` 转换并打开对应弹窗；
- 重置密码和邮箱验证 token 参数正确传递；
- 固定 `auth` 值外的参数不会渲染任意步骤；
- 刷新恢复弹窗；
- 关闭清理参数；
- 浏览器后退关闭、前进恢复；
- 安全 redirect 校验；
- token 不进入聊天内容和普通日志。

### 7.2 弹窗生命周期

必须覆盖默认不自动弹窗、打开、关闭按钮、遮罩、Escape、焦点、背景不可交互、单实例、步骤切换、响应式和深色主题。

### 7.3 统一拦截

必须覆盖发送按钮、Enter、语音、文件、历史、会话管理、Agent、插件、账户、余额和订单。验证未登录时：

- 原 action 未执行；
- 对应接口未调用；
- 不创建待执行队列；
- 弹窗只打开一次；
- 输入内容保持；
- 登录后不自动重放。

### 7.4 认证回归

保留并覆盖登录、注册、找回密码、重置密码、2FA、备用码、邮箱验证、Turnstile、LDAP、OAuth/OpenID/SAML 的成功、失败、限流、封禁、未验证、倒计时和错误提示场景。

### 7.5 匿名工作台

验证未登录时聊天壳层可见、输入可编辑、受保护数据不加载、受保护控件隐藏或禁用，且不会因为认证状态为空而渲染空白页面。

### 7.6 核心验收标准

1. 未登录首屏是聊天工作台，不是独立登录页。
2. 未登录输入有效问题并发送时，弹出登录弹窗且不发送请求。
3. 登录弹窗关闭或登录成功后，问题仍在输入框中。
4. 登录成功不自动发送，用户再次触发才发送。
5. 所有受保护操作使用统一拦截。
6. 原认证功能全部保留且可用。
7. 旧认证链接继续可用并转换为聊天背景弹窗。
8. 背景聊天界面不卸载、不重置。
9. 2FA `tempToken` 只保存在内存，不进入 URL。
10. 不新增二维码、手机号、匿名模型请求或后端认证架构。

## 8. 非目标

本次不重新设计聊天工作台、模型选择器、侧边栏、支付业务或第三方身份提供商页面；不修改后端登录、注册、密码、2FA、限流、封禁、邮箱验证和 OAuth 规则。
